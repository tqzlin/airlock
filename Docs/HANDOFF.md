## 2. Build, run, test - the cycle
1. Close THIS checkout's editor if it is open: `powershell -NoProfile -ExecutionPolicy Bypass -File Scripts\close-editor.ps1` (WM_CLOSE to the editor whose command line names this checkout's `.uproject`, waits 90 s, kills only then - a modal dialog). Never close editors by process name: another checkout's editor may be running side by side (section 7). Since 2026-09-12 `build-editor.bat` passes `-NoHotReloadFromIDE`, so an editor on *another* checkout no longer blocks the build (UBT's Live Coding lock is keyed on the shared engine `UnrealEditor.exe`); your own editor still has to be closed because its loaded `UnrealEditor-Airlock.dll` cannot be relinked (the build then fails with LNK1104 instead of the old Live Coding message).
2. Build: `Scripts\build-editor.bat` (= `Build.bat AirlockEditor Win64 Development`, 5-15 s incremental). A failing build leaves the editor closed - fix and rebuild.
3. Relaunch: `Scripts\run-editor.bat`. The Unreal MCP server starts with the editor on `http://127.0.0.1:8000/mcp` (~60-90 s until the port listens; `AIRLOCK_MCP_PORT` overrides the port for a second checkout, section 7). Wait ~30 s more before driving it.
4. Tests: `Scripts\run-tests.bat Airlock` (headless), or in-editor through MCP `AutomationTestToolset` (`DiscoverTests` -> `RunTestsByFilter 'Airlock'` -> `GetTestStatus` until not running -> `GetTestResults`; the status JSON carries `numComplete`/`numPassed`/`numFailed`). 34 tests exist (2026-09-12, after M3-3); all must stay green.
5. PIE proofs: `Scripts\verify-loop.ps1` (section 4), `Scripts\verify-voyage-clock.ps1` (M3-1), `Scripts\verify-ship-graph.ps1` (M3-2) and `Scripts\verify-incidents.ps1` (M3-3). Run the ones your task can affect; attach their tails. Each takes about a minute and starts/stops its own PIE.

Live Coding (`Ctrl+Alt+F11` inside the editor) is untested in this project; the close/build/reopen cycle is the known-good path.

## 3. Driving the editor (Unreal MCP)
- Client: `Scripts\lib\mcp.ps1` - dot-source it in PowerShell 5.1: `Mcp-Init`, then `Mcp-Call <toolset> <tool> @{...}` returns `{ok, text, json, images}`. It talks to port 8000 unless `$env:AIRLOCK_MCP_PORT` says otherwise (set it in the shell that runs the proof scripts). Toolset name constants are at the bottom of the file (`$TS_Scene`, `$TS_Asset`, `$TS_Object`, `$TS_App`, `$TS_Logs`, `$TS_Tests`, `$TS_Slate`, ...). Any MCP client works too (Streamable HTTP, no auth, loopback only).
- Batching: `editor_toolset.toolsets.programmatic.ProgrammaticToolset.execute_tool_script` runs a sandboxed Python `run()` that calls `execute_tool(name, json)`; hundreds of calls per round-trip. An inner tool error raises *and* fails the whole call, so isolate risky calls in their own script. `import unreal` is not available.
- Console commands in PIE: write one command per line to `Saved\AgentConsole\commands.txt` (create the folder if needed). `UAgentConsoleSubsystem` (editor builds, lives on the GameInstance, so only while PIE runs) polls the file every 0.5 s, runs each line through the first local player controller, logs `LogAirlock: AgentConsole: <line>` and deletes the file. Wait for the file to disappear before sending the next one. This needs no window focus. The older way - Slate `Snapshot` -> the `textbox` after `text "Cmd"` -> `Type(ref, cmd, submit=true)` - only works while the editor is the active window and hangs otherwise; avoid it. Never `Click` a widget matched by loose text ("Close" once matched "Close Unreal Editor").
- Exec helpers on `AAirlockPlayerController` (send them through the file console): `AirlockBoard` (open the departure UI), `AirlockBook <0-2>` (book today's voyage of that type), `AirlockWarp x y z` (server teleport; the pawn falls and settles, so `AirlockWhere` afterwards gives you the walking surface at that spot), `AirlockWhere` (log map + pawn/view location - run it before believing a dark or empty frame), `AirlockVoyageClock <s>` (seconds left on the voyage), `AirlockShipStatus`, `AirlockFault <LineId> <None|Leak|Short>`, `AirlockDamage <ModuleId> <n>`, `AirlockRepairModule <ModuleId> <n>`, `AirlockHold <ActorLabel>` / `AirlockRelease` (the hold-E verb by label; must be within reach), `AirlockIncident <CoolantLeak|PowerShort|ModuleDamage> [TargetId] [Magnitude]` (fire one incident now; omitted target = first eligible, omitted damage = 40), `AirlockIncidentSchedule` (dump the voyage's incident schedule and cursor). Incidents only exist on a ship section with an active voyage; on the hub the helpers log `no active incident director`.
- Captures: `EditorToolset.EditorAppToolset.CaptureViewport` (editor camera; takes a transform) and `CaptureEditorImage` (whole editor window, i.e. the PIE view). Give exposure 6-10 s to settle after a spawn or warp before capturing.
- `StartPIE` spawns wherever the editor camera is unless you pass `startTransform`; for a real player view pass the PlayerStart (hub: `-5640 1560 118`).
- The full lesson list (property quirks, level load rules, what closes the editor) is in `AGENTS.md` "Driving the editor".

## 4. The loop proof (`Scripts\verify-loop.ps1`)
Requires the editor open on StationHub with the MCP port up. It: starts PIE at the hub PlayerStart, `AirlockWhere`, warps to Dock B, `AirlockBook 0`, crosses the threshold (`-4265 1560 116`), waits for `Section Hauler_Mk1`, `AirlockWhere` (expects `X=-6660`), warps to the ship exit threshold (`-7015 1560 116`), waits for the return travel, `AirlockWhere` (expects `X=-5640`), stops PIE. Exit code 0 only if both arrivals landed at their PlayerStarts and `Voyage ... complete` was logged. Captures land in `Saved\AgentCaptures\`.

Useful coordinates (StationHub unless noted): hub PlayerStart `(-5640, 1560)` lower deck; Dock B door `(-4300, 1560, 20)` yaw 180, threshold `(-4265, 1560, 116)`, approach `(-4700, 1560, 116)`; departure board `(-4450, 1330)`; Dock A (sealed) `(-6980, 1560, 20)`. Hauler_Mk1: PlayerStart `(-6660, 1560)`, exit door `Airlock_ToHub` `(-6980, 1560, 20)` yaw 0, threshold `(-7015, 1560, 116)`.

Useful coordinates on the ship after the bridge graft (2026-09-12): east corridor dead-end junction `(440, -20)`, connector `X 620..980` on `Y -20`, bridge door wall at `X 980`, bridge floor `Z 22`, terminal at `(2010, 240)`; west hall walking surface `Z -65` (glass floor) with the entry platform at `Z 20` by the exit door. ## 5. Rules that bite
- Never save over pack assets (duplicate into `/Game/Maps` or `/Game/Airlock`). The two documented exceptions (Nanite, StarfieldFree collision) are already applied; see `THIRD_PARTY_ASSETS.md`.
- Server-authoritative gameplay: state changes on the server, replicate, clients predict at most. UI is local.
- C++ for systems; no UMG/Blueprint assets so far (widgets are built in C++ in `RebuildWidget`). Keep it that way unless a brief says otherwise.
- `load_level` refuses when the current or target level is dirty - `save_assets` first. Don't leave maps dirty at the end of a task.
- If the editor misbehaves (stuck dialog, MCP not answering), close it and relaunch rather than clicking around. Report what happened.
- PowerShell trap that cost an evening: a function named like a built-in alias (`Where`, `Select`, `Sort`, `Type`, `Copy`...) never runs - the alias wins and `Where` alone becomes `Where-Object`, which then *prompts on the console* ("Supply values for the following parameters: Property:") while the script's stdout is redirected to a log, so the run looks hung forever. Use Verb-Noun names for script functions.
- If `Windows list` returns `[]`, `Snapshot` is empty or `CaptureEditorImage` says "Failed to capture any editor windows", the editor window is minimized (MCP still answers). Run `Scripts\restore-editor-window.ps1` and retry. Captures need a visible window; console commands (file console) do not.
- Launch the editor with `Scripts\run-editor.bat` or PowerShell `Start-Process`, never with cmd `start` or as a plain child of your shell: a GUI process started that way inherits your stdout pipe, and whoever is waiting on that pipe (the agent runner, a Codex session) waits until the editor exits - hours.
- Codex sessions on stack run under a usage cap (roughly 100-200k tokens per window, then "try again at <time>"). Commit after every step; a resumed session must start from `git status`/`git diff` of the working tree, not from the brief.
- PowerShell variables are case-insensitive: `$res` and `$Res` are the same variable (one review script clobbered its results folder that way).
- The programmatic Python sandbox rejects `dict.get(key, default)`; use `d[key] if key in d else default`. `find_actors` with a `name` filter matches by substring, so re-check the label.
- The editor used to throttle itself to well under 1 FPS whenever it was not the foreground window (a human using the laptop, or another agent's window in front), which made PIE runs crawl and MCP calls take a minute each. `bThrottleCPUWhenNotForeground` is now off in `Config/DefaultEditorPerProjectUserSettings.ini` (and in the live editor settings); if runs are inexplicably slow, check that setting first (Editor Preferences > Performance > "Use Less CPU when in Background").

## 7. Working from Claude Code on stack (the preferred way for Claude from 2026-09-12)
- Start it from the repo root: `cd C:\Users\tclin\Desktop\ai_game_studio\Airlock` then `claude`. `CLAUDE.md` points at `AGENTS.md`; `.mcp.json` gives the session the Unreal MCP tools (`list_toolsets` -> `describe_toolset` -> `call_tool`, same toolsets as `Scripts\lib\mcp.ps1`) while the editor is open. Read `Docs/STATUS.md` before doing anything.
- The shell is a real Windows shell, so `Scripts\*.bat`, `git`, the proof scripts and the file console all work directly; no queue round trip. Suggested permission allowlist for a working session: `git *`, `Scripts\build-editor.bat`, `Scripts\run-editor.bat`, `Scripts\run-tests.bat *`, `powershell -NoProfile -ExecutionPolicy Bypass -File Scripts\*.ps1`. Everything else stays on ask.
- The two rules that still bite from a terminal: close the editor before `Build.bat` (Live Coding lock), and relaunch it only through `Scripts\run-editor.bat` / `Start-Process` - an editor started as a child of the session's shell inherits its output pipe and keeps the session waiting for hours.
- One driver per editor. Before touching PIE or loading levels, check nothing else is driving it: `Get-Process codex` (an Astra run), the runner window executing a queue script, or another Claude session. Long Astra runs are launched as background processes (`codex exec ... -` with the prompt on stdin, pattern `agent\done\171`) and waited on; do not drive the editor while one runs.
- Commit after every step, one task per `<agent>/<task>` branch, review + merge as in section 6. The file-queue runner (`ai_game_studio\agent\runner.bat`) stays available as the fallback for Cowork sessions and unattended jobs; Cowork's own shell cannot mount the folders, so from Cowork everything goes through the queue.
- Parallel work (set up 2026-09-12): Astra owns the checkout at `Airlock\` and the editor on port 8000 while it runs. Claude works in the worktree `..\Airlock-claude`: `Scripts\new-worktree.ps1 -Name Airlock-claude -Branch <claude/task> [-Build]` creates one (`git worktree add` on a new branch from `main`, a junction for every git-ignored pack folder, its own `Binaries\`, `Intermediate\` and `Saved\`), a build there succeeds while the other editor stays open (`-NoHotReloadFromIDE`; a full build took 46 s with UBA), and it runs a second editor on its own MCP port: in the worktree, `set AIRLOCK_MCP_PORT=8001` then `Scripts\run-editor.bat`; the same variable makes `Scripts\lib\mcp.ps1` and every proof script talk to that editor. Rules that keep the two apart: close only your own editor (`Scripts\close-editor.ps1`); the file console, captures and logs live under each checkout's own `Saved\`; the engine DDC is shared and multi-process safe; two PIE sessions at once share one GPU, so run long proofs one at a time when you can. Claude Code's built-in `mcp__unreal-mcp__*` tools follow `.mcp.json` (port 8000 = Astra's editor); from the worktree drive the 8001 editor through `mcp.ps1` in PowerShell, or start the Claude Code session inside the worktree after `claude mcp add --transport http unreal-mcp http://127.0.0.1:8001/mcp` there (user-scoped per directory, nothing committed). Branch rule unchanged: one task per `<agent>/<task>` branch, the reviewer merges into `main`; `Docs/` and `Scripts/` maintenance by Claude may land on `main` directly, after which the worktree branch merges `main` in.

End every task with: behaviour changed; files; test names added/changed and their result; the `verify-loop.ps1` tail and any extra `LogAirlock` lines; captures; open questions; anything touched outside the brief. Put it in the PR / final message, and keep the branch pushed or at least committed locally.
